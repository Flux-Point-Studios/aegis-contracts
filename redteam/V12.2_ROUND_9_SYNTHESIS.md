## A. Z3 conservation-law proof (formal slice)

**Tool**: Z3 SMT solver via `z3-solver` v4.16.0.
**Scope**: V12.2 fee math arithmetic — `calculate_fee_total`, `calculate_protocol_fee_split`, and the silent-absorb branch.
**Input domain explored symbolically**: `premium ∈ [1 ADA, 1M ADA]` × `fee_bps ∈ [1, 10000]` × `partner_share_bps ∈ [0, 2000]` × `partner_present ∈ {0, 1}`.

**Result: 9/9 invariants PROVEN UNSAT** (Z3 found no model violating any invariant in the full input domain).

| Invariant | Result |
|---|---|
| I1 CONSERVATION — `premium == net_pool_growth + fee_total` | ✓ PROVEN |
| I2 NON-NEGATIVE — `fee_total / team_cut / partner_cut >= 0` | ✓ PROVEN |
| I2b NET-POOL-GROWTH — `net_pool_growth >= 0` when `raw_fee >= min_utxo` | ✓ PROVEN |
| I3 FEE-CAP — `fee_total <= premium` when `premium >= min_utxo` | ✓ PROVEN |
| I3b FEE-FLOOR — `fee_total == min_utxo` when `raw_fee < min_utxo` | ✓ PROVEN |
| I4 PARTNER-CAP — `partner_cut_raw <= fee_total × 20%` | ✓ PROVEN |
| I4b SPLIT-SUMS — `team_cut + partner_cut == fee_total` | ✓ PROVEN |
| I5 SILENT-ABSORB — `partner_cut_raw < min_utxo => partner_cut == 0 AND team_cut == fee_total` | ✓ PROVEN |
| I6 TEAM-FLOOR — `team_cut >= min_utxo` whenever `fee_total > 0` | ✓ PROVEN |

**What this means**: at the arithmetic layer, V12.2's fee split is sound across the entire realistic input domain. No integer-truncation drift, no missing-min-utxo path, no partner-cap violation reachable by any combination of inputs.

**What this does NOT prove**: the validator's full transition function (oracle binding, pool-NFT routing, datum integrity, cross-protocol composition). Z3 covers the fee-math slice only. The auditor's formal-methods team is the right venue for whole-transition-function FV; this slice removes one of the easier surfaces from their plate.

Tool: `redteam/z3_conservation_proof.py` — re-runnable; ~0.1s total.

## B. Mutation testing — coverage observation

**Tool**: `redteam/mutation_tester.py` (single-operator mutation testing for Aiken).
**Validator**: `contracts/validators/pool.ak` (1473 lines).
**Mutations tested**: 292 candidate sites (after filtering out generic-type angle brackets like `<Input>` and function-return arrows `-> Bool`).

**Results**:

| Outcome | Count | Meaning |
|---|---|---|
| KILLED        | 16  | Aiken test failed — mutation detected (good) |
| SURVIVED      | 248 | All aiken tests still pass — **test gap** under aiken's eyes |
| COMPILE_ERROR | 28  | Type system caught it before tests ran |
| TIMEOUT       | 0   | n/a |

**Aiken-side mutation score: 6.1%** (KILLED / (KILLED + SURVIVED)).

### Interpretation — this is a coverage-architecture observation, not a security finding

The low mutation score reflects how Aegis's test surface is structured:

- **Aiken-side tests** focus on PURE HELPER FUNCTIONS (`calculate_fee_total`, `can_underwrite`, `partner_address_not_aliased`, etc.). 351 helper-level tests + 5 new R8 regression tests = 712 reported execution-units in `aiken check`.
- **Full validator branch coverage** lives in two surfaces aiken DOES NOT see:
  1. **`api/tests/*.py`** — 596+ pytest integration tests that build real PyCardano `ScriptContext` instances and assert validator pass/fail behavior end-to-end.
  2. **Live preprod transactions** — V12.2 R8 was just deployed and verified (per the `06125e0d…` init pool tx and ongoing chain state).

The 248 surviving mutations cluster on three structural patterns:

1. **Final `&&`-chains at branch entry** (lines 791, 1136, 1387 — the Underwrite, BatchUnderwrite, and AcceptCancellation accept-clauses). Each chain has 12-13 boolean guards. A `&&` → `||` mutation lets ANY single guard's True be sufficient — clearly insecure, but the aiken test suite doesn't invoke the validator with a specific guard-isolated failing condition.
2. **Immutable-datum equality chains** (lines 452, 677, 857, 1025, 1184, 1329 — `new_datum.foo == datum.foo && ... && ...`). Mutating `==` to `!=` would let pool-state tampering through. Same coverage gap — aiken tests don't construct a tampered-datum continuing-output ScriptContext.
3. **Helper-internal guards** (e.g., `consumed_policies_total_to` at lines 65/69/84). These ARE used by Claim/BatchClaim paths but the helper itself isn't unit-tested in aiken.

**What the auditor will notice**: an external auditor running mutation testing against pool.ak will see the 6.1% score and ask the same question we did. Our answer needs to be precise: "Coverage is in pytest + live preprod, not aiken-side." That's a defensible architectural choice (mirrors how MeshJS / Lucid-based projects structure their test surface) but **it's worth backfilling the highest-value branches with aiken-level ScriptContext tests** before the auditor's review.

### Recommended backfill (Tier-1 actionable, v12.3 or pre-audit)

Add aiken-side ScriptContext integration tests for these three branches at minimum:

| Branch | Hot lines | Mutation cluster | Backfill cost |
|---|---|---|---|
| Underwrite | 791 (final `&&`-chain) + 452 (PolicyDatum equality) | 12 + 9 = 21 survivors | ~3 happy-path + 3 negative-flow ScriptContext tests, ~half day |
| BatchUnderwrite | 1136 (final `&&`-chain) + 1184/1329 (immutable equality) | 12 + 7 + 7 = 26 survivors | similar |
| AcceptCancellation | 1387 (final `&&`-chain) + 1025 (immutable equality) | 11 + 7 = 18 survivors | similar |

Each "ScriptContext test" constructs a synthetic `Transaction` value with controlled inputs/outputs/redeemers and asserts the validator pass/fail bit. Aiken's stdlib supports this via the `cardano/transaction` module; existing test files in `lib/aegis/*.ak` already use this pattern at helper level — extending to the validator entry points is mechanical work.

Mutation report: `redteam/V12.2_ROUND_9_MUTATIONS_POOL.md`.

## C. Mechanism-design / economic adversary

**Tool**: dispatched adversarial agent (no spec-knowledge primed; full file-system access; strict-TDD rubric).
**Scope**: economic / game-theoretic exploits — explicitly NOT technical bugs (rounds 1-8 already covered those).
**Output**: `redteam/V12.2_ROUND_9_MECHANISM_DESIGN.md` (~2500 words).

**Findings**: 1 MEDIUM, 3 LOW, 1 INFO. **Zero HIGH, zero CRITICAL.**

| ID | Severity | Title |
|---|---|---|
| R9-MECH-1 | INFO | Partner uncompensated on Cancel for premiums < 10 000 ADA (silent-absorb threshold is 50× the Underwrite-side threshold; doc-only fix) |
| R9-MECH-2 | **MEDIUM** | **RemoveLiquidity front-run on imminent Claim** — when oracle prints ITM, watchful LPs can race-submit RemoveLiquidity to drain `available_liquidity` at pre-Claim NAV. Endemic to permissionless insurance pools. v12.3 fix: timelocked RemoveLiquidity or expected-loss exit fee. |
| R9-MECH-3 | LOW | Partner-share economics discontinuity at the 100-ADA premium boundary (frontend integrator misincentive; doc-only) |
| R9-MECH-4 | LOW | Stale-oracle Claim window when AegisSelf publisher pauses (70-min `valid_until` is a real economic exposure window; recommend tighter publisher SLA OR validator-side ceiling on `valid_until - observed_at`) |
| R9-MECH-5 | LOW | Claim/Expire 1-ms boundary gap (a tx straddling expiry fails both; ~0.5 ADA wasted fee, no value transfer) |

**Six surfaces tested and rejected**:
- partner-share griefing (attacker self-pwns 245×)
- alternate cancel cycles (mainnet config makes LP gain per cycle)
- user-as-partner self-deal (bounded by 20% cap, per spec §10.3)
- leverage gaming (intended LP risk per §10.1)
- treasury donation gaming (R8 confirmed closed)
- concurrent Underwrite race (eUTxO deterministic, no asymmetric harm)
- cross-asset basis arb (correlated tails → exactly priced)

**R9-MECH-2 deeper note**: this is the most interesting Round-9 finding because it's a *real* economic exposure but architecturally endemic — every permissionless insurance pool on EVM and Cardano has the same shape. Industry-standard mitigations are (a) timelock RemoveLiquidity (Compound-style); (b) expected-loss exit fee (Nexus-Mutual-style); or (c) tiered withdrawal queues. **Recommendation: v12.3 add a 1-block timelock on RemoveLiquidity (queue + 1-block delay before execute)** — this neutralises front-running because by the time the LP's withdrawal lands, the Claim has either succeeded (LP exits at post-Claim NAV) or been rejected (LP exits at pre-Claim NAV — fine). Effort estimate: ~1 day Aiken + ~1 day off-chain + ~1 day frontend. Not mainnet-blocking; queue this for v12.3.

**R9-MECH-4 operational note**: live `/api/oracle/price` currently reports `fresh: false` for all 4 AegisSelf assets. The publisher's `valid_until` ceiling is 70 minutes, meaning stale ITM prints stay claimable for up to 70 minutes after off-chain prices recover. **Recommendation**: either tighten the publisher's SLA to publish-every-15-min OR add a validator-side ceiling `valid_until - observed_at <= 15 min`. The validator-side fix is the harder version but eliminates the exposure structurally.

## What the auditor will still find that this round didn't reach

We surfaced and closed what we can reach internally. The auditor's value is in categories we structurally can't replicate:

1. **Whole-transition-function formal verification.** We did fee-math; they do every validator branch end-to-end (likely in K-Framework or Lean).
2. **Specialized cryptographer review.** We checked primitive composition. They check key-derivation safety under rotation, length-extension surfaces on hash-then-sign, signature malleability edge cases the language reference doesn't surface.
3. **MEV / block-producer ordering.** Cardano is deterministic but SPs choose inclusion. Are there pool states where an SP-attacker can profitably reorder? Hard to model without a Hydra cluster.
4. **Long-tail Conway era fields.** We handle `treasury_donation`; auditors will probe full Conway tx-body interaction including voting procedures, DRep certs, proposal procedures interacting with our validator.
5. **Auditor's own checklist from prior engagements.** Tacit knowledge of "this exact bug class" patterns from past Cardano engagements that aren't in any public report.

These are the categories the auditor's hourly rate is genuinely worth on. Round 9 was about clearing as much of the easier stuff off their plate as we could.
